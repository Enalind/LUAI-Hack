# Live draft and review provider

Implemented in CP3 on 21 November 2026. A follow-up live D1 contract/reference smoke PASSED using the key added to ignored `.env`: one draft call, no reviews/retries, 13,219 ms, seven claims/references and unchanged clinician decisions. CP6 subsequently ran three prompt-held-out cases in six calls with documented omissions/extra questions; independent human/clinical validation remains unperformed. This smoke alone does not establish demo readiness. See [EVALUATION_REPORT.md](EVALUATION_REPORT.md).

## Configuration and flow

Default `AI_MODE=mock` needs no credentials. Explicit `AI_MODE=live` requires `ANTHROPIC_API_KEY`; `ANTHROPIC_MODEL` defaults to `claude-sonnet-5-5`. Keep credentials in ignored `.env.local` or server environment settings, then restart the local server. The live UI displays its mode and explains that fictional source text goes to Anthropic and generation may incur a cost.

`LiveProvider` uses `createAnthropic({ apiKey })` and a direct model instance. Draft generation exposes only `search_diagnosis_codes`, backed by the bundled official ICD-10-SE 2026 index, and allows at most four model steps. Review exposes no tools. Neither operation enables native citations or uses a gateway. The catalogue tool cannot change clinician decisions and its results cannot be used as patient evidence. Unknown, unspecific or unsuitable primary codes are rejected by application code before either provider operation; see [catalogue provenance](../data/README.md). Generation uses `generateText` with `Output.object` and the shared narrative schema, matching the installed `ai@7.0.179` / `@ai-sdk/anthropic@4.0.107` APIs and [official structured-output documentation](https://ai-sdk.dev/docs/ai-sdk-core/generating-structured-data) and [direct Anthropic provider documentation](https://ai-sdk.dev/providers/ai-sdk-providers/anthropic).

Current prompt identifier: `swedish-draft-v5-fk-parts` in `lib/server/prompts.ts`. Source passages are serialized as JSON in one user message, separate from the system instructions. The prompt asks for attributed Swedish narrative text, preserved negation/uncertainty, exact source IDs/quotes, focused gap questions, and no fabricated clinical decisions. The existing clinician diagnosis is provided as read-only DFA context. Leave extent and dates are omitted from draft context; all decisions are copied directly from the immutable source snapshot into the application response. Both live prompts include the pinned source-linked [FK guidance ruleset](FK_GUIDANCE.md), recorded as `guidanceVersion` in metadata. These instructions are not proof of semantic support or complete injection resistance.

The provider validates structured results and every citation. Empty draft sections must have information gaps. Refusals, unexpected finish reasons and truncation remain failures, including when returned text happens to be valid JSON. A live draft with missing, foreign or mismatched evidence is rejected with `INVALID_MODEL_OUTPUT`. No successful empty result or mock fallback is substituted.

CP4 originally added live review with `swedish-review-v1`; the current review prompt is `swedish-review-v3-fk-guidance`, retaining phrase targets and adding mandatory per-rule checks and allowlisted guideline links. It sends validated source passages and the current draft as data, checks four semantic categories, and validates every proposed target and citation. Code integrity/empty-field checks are independent of the model and survive its failure or empty finding list. Review is explicitly started by the user, uses one attempt and no automatic retries, and does not mutate the draft. See [REVIEW.md](REVIEW.md).

The current prompt and diagnosis tool have deterministic transport coverage, including a complete tool-call/result/final-output round trip. No new live provider calls were made for this dashboard update. The historical smokes and held-out evaluation below used `swedish-draft-v1`; their results do not validate the updated prompt. A live draft operation can now make multiple provider requests when it uses the lookup tool.

## Runtime limits and errors

- Maximum output: 12,000 tokens per model step, including any model reasoning charged within that step. Drafting permits up to four steps; review uses one.
- Draft requests explicitly set low effort so default model thinking does not consume the document output budget. Review explicitly uses medium effort for the expanded seven-rule review; drafting remains low effort.
- Output-limit truncation is reported as a specific length-limit failure, including when the SDK throws while parsing incomplete JSON. Other malformed output remains a format error. No automatic format/truncation retries are added.
- One shared 60-second deadline per operation covers attempts and retry waits. SDK retries are disabled; drafting allows at most one extra attempt for HTTP 429/5xx, while review allows no retries. Abort signals are passed through, and an outer deadline still returns a safe timeout if a transport ignores cancellation.
- `Retry-After` seconds, HTTP dates and `retry-after-ms` are respected. A delay over 5 seconds, or one that cannot fit the remaining budget with a 1-second reserve, returns a retryable error immediately. Without a usable header, the initial retry wait is 750 ms. Longer requested waits are never shortened.
- Authentication/model-access 4xx errors are not retried. Unknown errors and raw SDK/provider error bodies are not returned. No source/model prose is logged by application code. SDK telemetry and input/output recording are disabled, and raw request/response retention is explicitly disabled.
- The browser timeout is 70 seconds, allowing the server's safe error to return. Cancellation is best effort and does not guarantee provider billing stops.
- Both Node.js routes export `maxDuration = 120`, using the [documented Next.js App Router configuration](https://vercel.com/docs/functions/configuring-functions/duration). The 120-second target fits the documented 300-second Fluid Compute Hobby limit; actual account settings have not been inspected. Vercel supports explicit mock or live mode; live requires a server-only key. See [DEPLOYMENT.md](DEPLOYMENT.md); no deployment has occurred.

Success metadata contains explicit live mode, the provider-reported model ID (falling back to configured ID), prompt version, measured latency, and SDK-reported input/output/total/reasoning tokens. Missing usage values remain null. Failed-call usage is not exposed by the error contract and must not be assumed to be zero. No raw provider body, source text, prompt or credential is added to error responses.

## Explicit smoke command

Run `npm run smoke:live` only when a live test is intended. The wrapper announces **one potentially billable draft operation, zero review operations and no retries** (up to four provider requests if the diagnosis tool is used) before launching it. It uses fictional Swedish D1 and opts into live mode for that command, independently of the app's mock default. Ordinary `npm test` and `test:e2e` never run this test or load real credentials.

Without a key, the wrapper prints NOT RUN, makes zero calls and exits 2. With a key, it records a sanitized `.local/live-smoke-result.json`; `.local/` is ignored. The report contains model/prompt identifiers, time, usage, counts and contract/reference checks, or a safe failure code. It contains no source text, model prose or credentials. It is a contract/reference smoke test, not a clinical review or held-out evaluation. `npm run eval:live` now runs the bounded, frozen H1–H3 evaluation (at most six requests, no retries, `-- --limit 1|2|3` supported). Validated fictional observations are deliberately retained in ignored `.local/held-out-observations.json`; committed summaries contain metadata/counts and implementation-agent adjudication, not raw model prose. Failed cases remain in the denominator. See [EVALUATION_REPORT.md](EVALUATION_REPORT.md).

`npm run smoke:review` separately announces one review, zero live drafts and no retries, selecting only its own test. It prepares a corrupted fictional D1 draft through the mock provider, checks the real review contract/reference validation and records the expected omission probe in `.local/review-smoke-result.json`. One CP4 run passed and detected the omission; additional findings and general clinical quality have not been clinically adjudicated. These commands never select both live tests together.

## Longer-example live failure and fix — 21 November 2026

The longer D1 example reproduced the user-reported format failure in one live operation, with retries disabled. The provider returned `max_tokens` at 6,000 output tokens and an incomplete JSON object. It was an output-budget failure, not evidence of a schema or credential configuration problem. The previous generic SDK-error mapping hid that distinction.

After increasing the cap to 12,000 and setting low draft effort, the same example passed a live operation in 26,619 ms: 14 claims, 20 exact references, clinician decisions preserved, 14,282 input tokens and 3,844 output tokens. The response ended normally. No review or held-out evaluation was run for this fix. The configured model was `claude-sonnet-5-5`; prompt `swedish-draft-v2-icd`. These are contract and source-reference checks, not independent clinical validation.

The explicit draft smoke now records safe diagnostic metadata (stop reason, content-part types, token counts, output character count and schema issue paths) in its ignored local report. It does not retain raw source/model prose or credentials. A regression test covers a JSON response cut off mid-object; malformed output and invalid references still fail validation.

## Exact phrase annotations — 21 November 2026

Draft claims now require `evidenceSpans` in the live output: `{text, occurrence, referenceIndices}`. Text must match an exact phrase in the statement; occurrence is one-based and evidence indexes are zero-based within that claim. Every declared reference must be reachable through an annotation. Application output keeps the field optional for older drafts; editing clears anchors, and no fuzzy matching is used. The server rejects invalid targets rather than marking unrelated words. Source-ID and exact-source-quote validation are unchanged.

Live review requires `targetSpan: {text, occurrence} | null`. A targeted finding must match current claim text. Missing facts and source-supported additions have no phrase to mark and use null targets; the UI highlights the field heading. The review pane retains explicit accept/dismiss decisions. Old review marks are removed after edits.

Checks passed: 239 deterministic tests; 34 existing browser flows plus two phrase-specific flows; typecheck/production build. Live D1 draft verification passed in 17,291 ms with 8 claims, 12 references and no span-alignment errors. The live omission-review probe passed in 44,664 ms with 5 findings, 1 phrase target and the expected work omission detected. Initial live attempts failed validation; subsequent explicit probes passed, with no automatic retries. Those failed results are not treated as successful or excluded from this account. No source/model prose is retained in the local diagnostic reports. This does not establish clinical quality or a success rate, and the frozen held-out set was not changed or rerun.


## FK guidance and literal text parts — 21 November 2026

Current prompts are `swedish-draft-v5-fk-parts` and `swedish-review-v3-fk-guidance`, both using `fk7804-2026-11-21.v1`. Guidance is included unconditionally in system instructions. Live review must return seven consistent rule checks and applicable rule IDs on every finding; the server validates that coverage and the guidance version. Rule explanations and official links are resolved locally. Draft output uses literal `textParts`; application code derives the existing claim text and exact phrase spans, retaining strict source quotation validation.

Final live D1 drafting passed in 22,015 ms with 7 claims, 15 references and 17 spans. Guided omission review passed in 14,422 ms with 5 linked findings, 4 phrase targets and complete rule coverage. Initial probes hit a default-effort review timeout and a v4 draft phrase mismatch; those failures led to explicit medium review effort and v5 text-part assembly. Four explicit live probes total, without automatic retries. See [guidance scope and verification](FK_GUIDANCE.md); these checks do not establish clinical adequacy or validate the earlier frozen held-out results against the new prompts.
