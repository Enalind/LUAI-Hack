# Evaluation rubric and adjudication record

Implementation-agent source comparison (AI-assisted), not independent human or medical validation. The cases and answer keys were authored by the implementation agent, not a clinical gold-standard panel. Facts and answer keys were written before provider execution. This detailed recording rubric expands the pre-existing implementation-plan metrics; it was written during the run, before inspecting outputs. The evaluation uses no second model or automatic semantic grader. Exact citation/invariant checks are code-based; fact support, attribution, omissions and false alarms require explicit developer adjudication of the returned text against the prewritten keys.

For each H1–H3, record completion separately for draft and review. Keep refused, timed-out and invalid outputs in the case denominator. An uncompleted semantic measurement is N/A, not zero. Record model/prompt identities, SHA-256 freeze, operation/HTTP request counts, latency and reported input/output/reasoning/total usage. Unknown failed-call usage remains unknown. Reasoning is a subset of output and is not added again to totals.

1. **Facts retained:** for every keyed fact, identify supporting draft claim IDs in its intended field. Give partial/missing facts a failed item; do not use exact prose equality. Record content retention separately from strict prewritten field matching so a field-annotation error in the key is visible rather than silently rewritten. Count correct items / all keyed facts, with reasons for any miss.
2. **Unsupported claims:** inspect every substantive claim card. Mark it unsupported if it introduces an unsupported substantive fact, causal judgment or certainty. Count affected cards / all substantive claim cards; compound cards count once. List affected IDs and reasons. Exact-quote integrity is a separate measurement.
3. **Attribution:** inspect every claim card where patient report, examination, question or clinician assessment origin matters. Count correctly attributed cards / relevant cards. List errors. H1's denial must remain a patient denial, and H3's unanswered question must not become a finding.
4. **Gaps:** evaluate each prewritten expected gap. Record separately whether the draft's questions already surface it and whether final code+model review findings give an actionable question or warning for it. Cite finding IDs. Multiple findings for one gap still count once. H2's conflict may be correctly retained in draft text even if the reviewer misses it; disclose both.
5. **False findings:** classify each finding on adequate H1 as warranted, false alarm or unadjudicated. Count false / all H1 findings and state the number of adequate cases assessed (one). Zero findings means a 0/0 N/A finding ratio, not a demonstrated zero false-alarm rate. Do not assume an unexpected finding is false without reading it.
6. **Decisions:** count differences for each explicit decision field from the immutable input. Application passthrough is code-enforced; also inspect narrative/proposed changes for invented diagnosis, extent, dates or examination findings. A critical violation prevents calling local live behavior demo-ready, even if string/schema checks passed.

Do not calculate clinical success probabilities, time savings or approval improvements from this small set. A contract pass is not a semantic pass. Review suggestions remain unaccepted during evaluation; classify harmful proposed text separately from generated draft text. Do not tune or automatically rerun failures within the call budget.
